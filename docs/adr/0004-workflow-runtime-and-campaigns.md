# ADR-0004：工作流草稿、不可变运行图与 Campaign

- 状态：Accepted
- 日期：2026-07-30

## 背景

早期 Web POC 的节点位置主要保存在浏览器，工作流既不能可靠编辑，也没有区分“正在修改的图”
和“实际运行过的图”。长期筛选若直接复用节点图，又会把候选管理、运行历史和科研决策混在一起。

## 决策

CatEx 使用四层记录：

1. `WorkflowDraft`：每个项目只有一个可覆盖草稿，使用 SHA-256 乐观并发检查；
2. `WorkflowRevision`：发布时按图内容寻址，发布后不可修改；
3. `WorkflowRunGraph`：从发布版本复制的不可变运行快照；
4. `WorkflowNodeAttempt`：节点的排队、运行、成功、失败、取消等状态只追加记录。

Quick Build 与高级节点图编辑同一份草稿。CHGNet、VASP 优化、静态、频率、DOS 和 MD 节点会
编译成显式阶段计划；编译本身不创建输入、不运行命令、不连接 HPC。实际远端操作继续经过项目
输入检查、目录创建、提交和取消等独立权限门。

Campaign 不使用另一套科学工作流。它引用可选的工作流版本，并追加：

- candidate：结构 Artifact、设计变量和状态；
- decision：动作、依据、关联候选和证据摘要。

Campaign 主记录是机器可读 JSON；报告或 Markdown 只是投影，不是权威数据源。

## 后果

- 浏览器 `localStorage` 只用于尚未归属项目的临时图；项目工作流以后端草稿为权威；
- 已运行图不会因之后拖动节点或修改参数而变化；
- 节点重试不会覆盖早先失败证据；
- 文献复现、原创研究和实验解释继续共用同一核心；
- 自动续算、自动科学参数修复和无人值守批量提交仍不在本 ADR 的授权范围内。
